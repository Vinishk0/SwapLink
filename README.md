# SwapLink — бот-калькулятор обмена с реферальной программой

Telegram-бот для обменника: считает обмен по вашему курсу, принимает заявки и полностью
ведёт реферальную программу. **Бот не проводит сделки и не переводит деньги** — расчёт и
учёт, сделку выполняет оператор, подтверждая заявку в админ-панели.

Курс админ задаёт финальный, уже со своей маржой: **никакой комиссии бот не добавляет и
нигде её не показывает** — пользователь видит только курс, сумму и свою реферальную скидку.

Интерфейс — **одно сообщение**: любое нажатие кнопки редактирует его, а сообщения
пользователя бот удаляет сразу после обработки, поэтому чат не разрастается.

## Правила программы

| Кто | Что получает | Ограничение |
|-----|--------------|-------------|
| Приглашённый (реферал) | **+0.5%** сверху к сумме обмена | Только первые **3** проведённые сделки |
| Пригласивший (реферер) | **0.5%** от объёма каждой сделки реферала | Бессрочно, без лимита |

* Переход по ссылке `t.me/<bot>?start=ref_CODE` закрепляет реферала **навсегда и автоматически**.
* Пришедший сам может ввести чужой код вручную — но только **до первой проведённой сделки**.
* После 3-й скидки бот сообщает рефералу, что скидки закончились, и напоминает,
  что его собственная ссылка продолжает приносить доход.
* Начисления копятся на балансе в базовой валюте (`BASE_CURRENCY`, по умолчанию USDT).
  Админ может выплатить их деньгами или зачесть скидкой в обмен — в обоих случаях
  сумма списывается с баланса, а «всего заработано» остаётся неизменным.

Проценты, лимит скидок и базовая валюта настраиваются в `.env` — код ничего не хардкодит.

## Возможности

**Пользователь**
* 💱 Калькулятор: направление → сумма → курс, скидка, итог к получению.
* ✅ Заявка оператору одной кнопкой, отмена своей заявки, история заявок со статусами.
* 👤 Личный кабинет: реферальная ссылка (кнопка «Скопировать» + «Поделиться»),
  сколько приглашено, сколько заработано всего, доступный баланс, выплачено.
* 🤝 Если пользователь сам реферал — видит, кто его пригласил, сколько этот человек
  заработал на программе всего, и сколько скидок у него осталось.
* 💸 История начислений и список своих рефералов.

**Администратор** (`ADMIN_IDS`)
* 🔔 Новая заявка приходит в чат админа отдельной карточкой с кнопками
  «Провести», «Отклонить», «Сумма», «Клиент». Карточка живёт до решения по заявке,
  обновляется при любом изменении сделки и удаляется, когда заявка проведена или отклонена.
* 📋 Очередь заявок: карточка сделки, подтверждение, отклонение с причиной,
  корректировка суммы с автоматическим пересчётом бонуса.
* 👥 Пользователи: поиск по ID/@username/имени/реф-коду, карточка с балансом и рефералами,
  блокировка, история операций.
* 💰 Операции с балансом: выплата, зачёт в обмен, ручная корректировка (+/−).
  Пользователь получает уведомление о каждой операции. Если оператор пришёл к клиенту
  из карточки заявки, списанные бонусы сразу видны в этой заявке отдельной строкой
  «Зачтено с баланса» и в итоговой сумме к выдаче.
* 💱 Курсы: валюты (курс к базовой), направления (курс вручную или авто-кросс,
  лимиты, вкл/выкл).
* 📊 Статистика: пользователи, рефералы, объём, начислено/выплачено, остаток обязательств.

## Быстрый старт

### Docker (рекомендуется)

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN` и `ADMIN_IDS`, затем:

```bash
docker compose up -d --build
```

Поднимутся PostgreSQL, Redis и бот; миграции применяются автоматически при старте.
Логи: `docker compose logs -f bot`.

### Локально (без Docker)

```bash
python -m venv .venv
```

```bash
.venv\Scripts\activate
```

```bash
pip install -e ".[dev]"
```

Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `ADMIN_IDS`
(один ID или несколько через запятую). `DATABASE_URL` по умолчанию — SQLite в `data/`,
никакой инфраструктуры не нужно. Запуск:

```bash
python -m app
```

Таблицы создаются автоматически при первом запуске; для управляемых миграций используйте
`alembic upgrade head`. Если конфигурация неполна, база недоступна или токен неверный,
бот пишет понятную причину вместо трейсбека.

### PyCharm

В репозитории лежат готовые конфигурации запуска (`.run/`) — они появляются в списке
сразу после открытия проекта:

* **Bot (python -m app)** — запуск бота;
* **Tests (pytest)** — весь тест-сьют;
* **DB migrate (alembic upgrade head)** — применить миграции;
* **DB reset (scripts/reset_db)** — снести базу и залить демо-данные.

Останется указать интерпретатор: *Settings → Project → Python Interpreter →
Add Local Interpreter → Existing → `.venv\Scripts\python.exe`*. Файл `.env` бот читает сам,
плагин EnvFile не нужен.

Чтобы сразу получить рабочие направления обмена, поставьте `SEED_DEMO_DATA=true` —
будут созданы USDT/USD/EUR/RUB и четыре пары. Иначе добавьте валюты через
админ-панель: `/admin` → «Курсы и направления».

## Конфигурация

Все параметры — в `.env` (см. `.env.example`).

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `BOT_TOKEN` | Токен от @BotFather | — |
| `ADMIN_IDS` | ID админов через запятую | пусто |
| `DATABASE_URL` | Строка подключения SQLAlchemy | SQLite в `data/` |
| `REDIS_URL` | Хранилище FSM; пусто — в памяти | пусто |
| `BASE_CURRENCY` | Учётная валюта балансов | `USDT` |
| `REFERRAL_DISCOUNT_PERCENT` | Скидка рефералу | `0.5` |
| `REFERRAL_BONUS_PERCENT` | Доля реферера со сделки | `0.5` |
| `REFERRAL_DISCOUNT_LIMIT` | Сколько сделок со скидкой | `3` |
| `THROTTLE_INTERVAL` | Антифлуд: секунд между апдейтами (0 — выключить) | `0.35` |
| `SEED_DEMO_DATA` | Создать демо-валюты при пустой БД | `false` |
| `SUPPORT_USERNAME` | Контакт оператора в сообщениях | пусто |
| `TIMEZONE` | Часовой пояс отображения дат | `Europe/Moscow` |

## Как устроен проект

```
app/
├── config.py            настройки (pydantic-settings) и .env
├── db/
│   ├── base.py          Base, TimestampMixin, тип Money (Decimal без потерь)
│   ├── engine.py        async-движок и фабрика сессий
│   ├── models/          users, currencies/pairs, orders, transactions
│   └── seed.py          создание схемы и демо-данные
├── services/            вся бизнес-логика, не зависит от Telegram
│   ├── exchange.py      расчёт котировки, курсы, направления
│   ├── referrals.py     ссылки, привязка рефералов, сводка
│   ├── orders.py        жизненный цикл заявки, начисления при подтверждении
│   ├── balance.py       баланс и журнал транзакций
│   └── stats.py         агрегаты для админки
├── bot/
│   ├── runner.py        composition root: middlewares + роутеры + polling
│   ├── ui.py            «один экран»: редактирование и удаление сообщений
│   ├── notifications.py пуши пользователям и карточки заявок для админов
│   ├── middlewares/     сессия БД, регистрация пользователя, антифлуд
│   ├── keyboards/       клавиатуры и типизированные CallbackData
│   ├── handlers/        user-флоу + admin/ (заявки, пользователи, курсы)
│   └── texts.py         все тексты в одном месте
└── utils/format.py      форматирование денег, процентов, дат

scripts/reset_db.py      быстрая очистка базы для разработки
```

Ключевые решения:

* **Слой сервисов ничего не знает об aiogram** — его можно вызвать из тестов, скрипта
  или будущего веб-API; хендлеры только собирают ввод и рисуют ответ.
* **Деньги — только `Decimal`.** Тип `Money` хранит NUMERIC в Postgres и строку
  фиксированной точности в SQLite, чтобы не терять копейки на float.
* **Начисление происходит один раз — при подтверждении заявки.** Право на скидку
  перепроверяется в момент подтверждения, поэтому параллельные заявки не могут
  «размножить» лимит из трёх скидок.
* **Баланс денормализован** (`users.balance`), но каждая его копейка объяснена строкой
  в `transactions` — это аудит и история для пользователя.
* **Один экран на чат.** `app/bot/ui.py` хранит id сообщения бота в FSM и редактирует
  его; сообщения пользователя удаляются. Исключение ровно одно — карточка новой заявки
  в чате админа: её нельзя перерисовывать навигацией, она ждёт решения по сделке.
  Важные уведомления отправляются новым сообщением (редактирование не даёт пуша),
  старое при этом удаляется — в чате по-прежнему одно сообщение бота.

## Разработка

```bash
pytest -q
```

```bash
ruff check app tests
```

Быстрая очистка базы во время разработки:

```bash
python scripts/reset_db.py --orders
```

`--orders` стирает заявки, транзакции и обнуляет балансы/счётчики, оставляя людей,
реферальные связи и курсы. Без флага сносится вся база целиком (`--seed` — сразу
создать демо-валюты, `--yes` — без подтверждения).

Новая миграция после изменения моделей:

```bash
alembic revision --autogenerate -m "описание"
```

CI (GitHub Actions) на каждый push и PR прогоняет ruff, тесты и сборку Docker-образа.
